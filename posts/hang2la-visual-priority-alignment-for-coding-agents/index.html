别再对着终端手打排期了：用拖拽看板接管 Coding Agent 的执行顺序

日常用 Claude Code、Codex、Antigravity 或者 Cursor 辅助写代码时，沟通往复最多的环节往往是给它定方向。

让它做一次架构梳理、排查历史代码或者拆解新功能，屏幕上会立刻多出十几个甚至二十个待办事项。现在的工具无论是走命令行终端，还是用各自的 Web 版、图形客户端（GUI），界面体验其实都不差。但不管放在哪个窗口里，吐出来的始终是一大串纵向平铺的文字列表，始终不是直观可归纳的分类框框。看到第十二条的时候，往往已经忘了第三条写的是什么。

更费劲的是调整优先级。模型给出的默认顺序很少能完全契合当前的业务重心。如果想让它按你的想法排期，传统做法是在对话框里手打一段话：“把第 3 项和第 7 项提前，第 2 项取消别做了，第 9 项延后处理，第 5 项排在第 7 项后面”。

敲这段话费时费力，稍微走神就会漏掉几项。更常见的情况是，模型读完这一长串绕口令式的自然语言批示，在后续执行时依然把轻重缓急搞混。原本用来写代码的时间，大量耗费在了对话框里反复确认和修整任务列表上。

如果嫌打字麻烦、干脆不做干预，任由 Agent 自行决定执行顺序，它又很容易把宝贵的算力和时间消耗在无关紧要的边缘需求上，真正急需交付的主干功能反而迟迟不动。

为了解决人和 Agent 对齐优先级的摩擦，我在自己的开源小工具 hang2la（h2l.kuhung.me）里加了一套零存储的视觉化任务对齐机制。

为什么现有的任务对齐方式在日常开发里不够顺手

面对多任务排期，市面上有几种常见的处理方式，但在高频的个人编码场景下各有短板：

对齐方式 准备成本 全局视野与调整速度 数据驻留与隐私 对 Agent 上下文的负担 主要短板
对话框手打自然语言批示 零成本 一维文本列表，扫视慢，手打修改耗时 留在当前会话 低，仅增加几轮对话 超过 5 项后极易说漏，模型容易理解偏差
IDE 内置 Plan / Todo 列表 零成本 纵向列表，支持简单勾选，难以做多档位分级 留在本地 IDE 低 缺乏清晰的主次档位，调整先后顺序仍然靠打字或改文本
本地 Markdown 文件 (TODO.md) 低，建个文件即可 纯文本跨行剪切粘贴，行数多时依然眼花 留在本地代码库 每次读写文件需消耗一定 Token 容易在仓库里留下临时脏文件，缺乏直观的图形分层
外部项目管理工具 + MCP (如 Linear / Jira) 高，需注册账号、配 API 密钥、装 MCP 服务 看板视图清晰，支持拖拽 上传至第三方云端服务器 高，几十个 MCP 工具定义常驻占用上万 Token 配置太重；内部接口名和业务表结构上传外部平台有隐私顾虑
hang2la 零存储浏览器看板 零安装，发一句提示词即用 二维五档看板，十秒内拖拽定生死 仅在浏览器本地内存，关闭即销毁 极低，仅一进一出两段简短文本 单次对齐工具，不做跨月的多人长周期追踪

很多开发者不愿意为了排个期去接 Linear 或 Jira 的 MCP，主要有三个现实原因：

第一，日常临时开发犯不着起一套重型基建。
很多时候我们只是在本地开个临时分支修一批 Bug，或者花半天时间重构一个模块。为了对齐十几个待办，专门去配 API 密钥、在项目里塞配置文件、检查 MCP 进程有没有掉线，属于高射炮打蚊子。

第二，外部 MCP 工具会无声吃掉大量上下文空间。
给 Agent 挂载一套完整的项目管理 MCP，光工具说明（Tool Definitions）就会在每一轮对话里占掉成千上万的 Token。上下文窗口被这些工具定义挤占后，留给代码分析和逻辑推理的有效空间反而变小了。

第三，业务代码的待办事项不想往第三方云端传。
Agent 拆出来的任务名称里，通常直接带着内部接口路径、核心数据表名、未公开的产品功能或者安全漏洞描述。把这些敏感信息同步到外部 SaaS 平台的数据库里，心里总归不踏实。

hang2la 是什么：用五档看板给任务定生死

hang2la（夯爆了）原本是一个用来盘点个人项目资产的 Tier List（层级清单）面板。它借用了大家熟悉的 S / A / B / C / D 五个档位（夯、顶级、人上人、NPC、拉了）。

这套分级心智用来给 Coding Agent 的待办任务定优先级，天然契合：

档位 标识 业务语义 Agent 拿到结果后的执行准则
S 夯 (Solid) 最高优先级 / 核心主干 最高优立即执行，集中算力与上下文优先交付
A 顶级 (Elite) 高优先级 / 关键里程碑 紧随 S 档之后推进，属于核心功能项
B 人上人 (Superior) 中优先级 / 正常排期 按序正常推进，在主干稳定后实施
C NPC (Normal) 低优先级 / 锦上添花 暂缓或最后处理，不占用主周期
D 拉了 (Lame) 明确放弃 / 伪需求 严格跳过或删除，不编写任何实现代码

在同一行档位内部，越靠左的卡片优先级越高。

当抽象的文字列表变成二维空间里的卡片后，人的决策动作变得非常直觉：看到核心主干任务，顺手往 S 夯 左边一拉；看到模型自作主张加出来的过度设计或无用兼容，直接拽进底部的 D 拉了。哪怕有二十个任务，在浏览器里扫一眼、拖几下，十秒钟就能把主次关系理得清清楚楚。

怎么用它接入日常开发工作流

整个过程不需要安装任何命令行插件，也不需要注册账号，三步走完一个闭环：

1. 让 Agent 生成排期链接

当你在 Claude Code、Codex、Cursor 或 Antigravity 里聊出一批待办事项后，直接在对话框输入这句指令：

阅读 https://h2l.kuhung.me/skill.md。把我当前项目里的待办任务排个期，按规范生成一个夯拉榜链接给我。

Agent 读取规范后，会把待办事项编码到 URL 的 Hash 参数里，直接给你吐出一个超链接（在 Mac 终端环境下，Agent 甚至可以直接调系统的 open 命令帮你把浏览器标签页弹出来）。

2. 在浏览器里拖拽理牌

点击链接，页面会自动进入专注的任务分诊模式。

你可以直接拖动卡片调整档位和左右顺序。如果你把某张卡片从 Agent 原本建议的档位挪到了新档位，鼠标悬停在卡片上时，右上角会轻量提示原来的档位（比如 原: B），平时则保持画面干净，不干扰视线。

3. 一键复制回传 Agent

排好顺序后，点击页面右上角的 「完成排序并复制」 按钮。

系统会自动把你调整后的最终结果和档位变更，整理成一段干净的人类批示写入剪贴板：

我已排定优先级，请按以下顺序执行：

【S 夯 - 最高优先立即开干】
1. 模块 A 重构（从 B 档调整至 S） - 核心主干重构
2. 修复线上支付回调异常

【A 顶级 - 高优推进】
1. 增加核心链路单元测试 - 覆盖率提升至 80%

【D 拉了 - 砍掉不做】
- 旧版 V1 接口兼容层

（请优先交付 S 级项，D 级已明确砍掉/跳过）

切回终端、客户端或网页对话框，按 Cmd+V 粘贴回车。Agent 收到这段明确的指令后，会自动跳过 D 档里的废弃项，严格顺着 S、A、B、C 的顺序开始写代码。

进阶用法：写进全局规则，省去每次手敲提示词

如果你经常需要做任务排期，可以把下面这段约定直接加进你的全局或项目规则文件里（比如 Claude Code 的 CLAUDE.md、Antigravity 的 GEMINI.md 或 Codex 的 AGENTS.md）：

## 任务优先级对齐规范
当梳理出的待办任务、重构项或候选技术方案超过 4 项，且需要人类确认执行优先级时：
1. 请参照 https://h2l.kuhung.me/skill.md 的规范，将待办项生成为 `https://h2l.kuhung.me/#b64:...` 排期看板链接。
2. 在 macOS 终端中可直接执行 `open` 打开该链接，等待人类粘贴回传排序结果后再按序编写代码，严格跳过「D 拉了」档位中的项目。

配好这一条之后，平时只要让 Agent 列计划，它就会自动把排期看板弹出来等你拍板，连提示词都不用再敲。

它是怎样实实在在提高编码生产力的

把长文本沟通换成看板拖拽，在实际写代码时能省下四块隐性成本：

第一，用二维空间直觉替代一维文本阅读。
人眼对颜色分层和空间位置的敏感度，远高于单调平铺的长文本段落。十几条任务摆在五个颜色分明的档位行里，哪个档位塞满了、哪个核心任务掉在了后面，一眼就能看穿，省去了在长列表里反复上下滚屏比对的脑力消耗。

第二，用「D 拉了」档位果断砍掉过度设计。
现在的 Coding Agent 非常喜欢自作聪明，顺手给你加一堆“向后兼容包装层”“未来扩展接口”或者“兜底轮询脚本”。以前在文字列表里很容易忽略这些夹带私货的任务，等它写出几百行冗余代码再去回滚，既浪费 Token 又污染上下文。现在看到这类伪需求，顺手拖进 D 档，回传指令里会明确标出“砍掉不做”，直接把过度设计掐死在动工之前。

第三，自动标注档位变更，帮模型校准业务重心。
当你把某项任务从 B 档提到 S 档时，复制出来的文本会自动带上 （从 B 档调整至 S） 的标记。这个标记等于在明确告诉模型：你刚才对这件事的重要程度判断错了。模型收到这种强反馈后，在后续写代码和分配注意力时，会明显向你提拔上来的模块倾斜。

第四，100% 内存运行，零隐私外泄与零上下文污染。
任务数据完全编码在 URL 的 # 号（Hash 片段）后面。按照浏览器标准，URL Hash 永远不会发送到服务端，解析和渲染全部在你的浏览器本地内存里完成。既保护了业务代码的隐私，又不像重型 MCP 那样常驻吞噬宝贵的会话 Token。

别让 Agent 在错误的分支上跑得太快

现在的 Coding Agent 执行速度越来越快，几分钟就能刷出成百上千行代码。

如果在最开始的几分钟里，人类只能眯着眼睛在几十条长文本里看个大概，或者花五分钟在对话框里敲一段绕口令式的批示，Agent 就会以极高的效率在错误的方向上狂奔：写出一堆过度设计的兼容层、修几个无关紧要的边缘 Bug，直到你不得不停下来帮它回滚代码、重整上下文。

面对几十项待办，花十秒钟把主次关系拖拽清楚，把伪需求甩进 D 档，是目前把控 Agent 执行方向成本最低的办法。

它不需要注册，不需要安装，关掉页面数据就从内存释放。

下次当你让 Claude Code、Codex、Cursor 或 Antigravity 梳理出计划时，直接把这行指令复制给它：

阅读 https://h2l.kuhung.me/skill.md。把我当前项目里的待办任务排个期，按规范生成一个夯拉榜链接给我。
